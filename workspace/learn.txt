# Flutter Riverpod: Best Approach Step-by-Step Guide

## 1. Core Basics
- **Providers**: Understand the concept of providers as 'containers' for state.
- **ProviderScope**: Must wrap your root application with `ProviderScope` to enable Riverpod functionality.
- **Widget Types**: Learn the difference between `ConsumerWidget` and `ConsumerStatefulWidget`.

## 2. Using the Generator (Modern Best Practice)
- **riverpod_generator**: Always use the code generator to reduce boilerplate and catch errors early.
- **@riverpod**: Use annotations for your providers.
- **Notifier**: Move from simple Providers to `Notifier` and `AsyncNotifier` for encapsulate logic.

## 3. Reading Providers
- **ref.watch**: Use inside the `build` method to observe changes and trigger UI rebuilds.
- **ref.read**: Use inside event handlers (like button clicks) to perform actions without listening for updates.
- **ref.listen**: Use to perform side-effects (like navigation or showing snackbars) when state changes.

## 4. State Invalidation & Disposal
- **ref.invalidate()**: Force a provider to refresh its data.
- **AutoDispose**: Automatically clean up resources when they are no longer in use.

## 5. Advanced Patterns
- **AsyncNotifier**: For complex asynchronous operations like API calls.
- **Testing**: Override providers in tests using `ProviderScope(overrides: [...])`.
- **Family**: Pass parameters to providers easily using code generation syntax.
